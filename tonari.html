チーム開発（4 人）・ JPHACKS 2026 ・ 2026.10

となり
詰まったときだけ声をかける、答えを言わない AI 家庭教師

紙に書いている手元をスマホで見て、手が止まったときだけ、答えではなく次の一歩を声と字幕で示します。JPHACKS 2026 に 4 人チームで出場し、Hack Day の 2 日間（10 月 17〜18 日）で作り、公開しました。

紹介動画を見る ↗ GitHub ↗
16/24 → 0/24ヒントに答えが漏れたのを見逃した件数（評価セット 55 件）
約 3 秒前詰まりを先読みして、ヒントを作り始める

目次

01概要

大会
JPHACKS 2026（大阪会場）。Hack Day 2026 年 10 月 17〜18 日
体制
4 人チーム。自分は API サーバ（状態の管理・ヒントの生成・答え漏れの検査）、手元の静止の判定、デプロイを担当。メンバーは学習者と運営の画面、キャラクターの切り替え、発表と実機での試験を担当
技術
Next.js・React・TypeScript・Tailwind CSS ／ FastAPI・Pydantic ／ Gemini API（構造化出力）／ VOICEVOX ／ Web Speech API ／ OpenAPI（API の仕様）
URL
github.com/jphacks/os_2601　紹介動画

02背景

家で一人で宿題を解いていて詰まったとき、今の中高生は AI に聞きます。ただし聞くには、写真を撮り、アプリを開き、質問を打つ必要があり、手が止まって紙から目が離れます。そして AI は答えを出します。

家庭教師は、隣で手元を見ていて、止まった瞬間に「どこまでできた？」と聞いてくれます。答えは言いません。となりは、それを家にあるスマホでできるようにしました。

  • 聞かれる前に気づく：手が止まったことを、映像の動きから判定する。
  • 答えを言わないことを、プロンプトだけに頼らず、サーバで機械的に守る。
  • 映像は残さない：送るのは動きの数値と、詰まったときの 1 枚だけ。

03担当したこと

01

手元の静止の判定

工夫
映像はブラウザの中で 64×36 に縮めて毎秒の差分を数値にし、映像そのものは送らず残さない。実機の iPhone で、書いているときと止まったときの値を測り、明るさの変化を除いて、静止に入る境目と抜ける境目を分けた（境目の近くで判定がばたつかないように）。
02

待たせない

工夫
詰まりの約 3 秒前に写真を送ってヒントを作り始め、詰まった瞬間に AI を待たずに声の合成に入る。
03

答えを言わない

工夫
AI に同じ呼び出しで問題も解かせ、ヒント文に答えや途中の値が含まれていれば、サーバで捨てて問い返しに差し替える。
結果
評価セット 55 件で、答え漏れの見逃しを 16/24 → 0/24 に減らし、誤検知は 0/31。ただし検査を直すのに使ったセットでの値で、答えを言い換えられると止められない。

04チームで並行して作るために

チームで開発経験があるのは自分だけでした。メンバーが AI（Claude Code や Codex）と一緒に画面を作っても、API や共通の処理を壊さずに済むよう、事前に仕組みを用意しました。

  • API の仕様とモックを先に用意：OpenAPI で仕様を決め、モックを用意して、画面を API の完成を待たずに並行して作れるようにした。
  • 担当外の変更を止める：人ごとに触ってよいフォルダを決め、git フック（pre-commit・pre-push）と CI で、担当外・保護ファイルの変更、main への直接の push、force push を止めた。
  • AI が最初に読む決まりと手引き：CLAUDE.md・AGENTS.md に担当と禁止事項を書き、開発に慣れていないメンバー向けに AI 開発のガイドを書いた。担当外の変更が要るときは、自分で直さず頼んでもらう流れにした。
